# Groceries

A simple, shared grocery list for the family. Mobile-first React site, served as static files from S3 through CloudFront, with a small Lambda + DynamoDB API behind API Gateway. Deployed with Terraform.

**MVP scope:** one shared list, no sign-in. Anyone with the URL can use it, so don't share the link publicly (see [Security](#security)).

## Design mockup

Open [`mockup/index.html`](mockup/index.html) in a browser — it's a standalone file (no build, no backend) showing the list, empty and dark-mode screens. The first phone is interactive. It uses the app's real stylesheet, so what you see is what ships.

## How it works

```
Phone ──► CloudFront ──┬─ /*      ──► S3 (private, via Origin Access Control)   static files
                       └─ /api/*  ──► API Gateway (HTTP API) ──► Lambda ──► DynamoDB
                          + secret header `x-origin-verify`
```

- **Frontend** (`frontend/`): Vite + React + TypeScript. Optimistic updates, and it polls every 5 s (and on app focus) so changes from other family members show up on their own. Installable to the home screen.
- **Backend** (`backend/`): TypeScript Lambda (Node 22) with a storage interface — DynamoDB in AWS, in-memory for tests and local dev.
- **Infra** (`infra/`): Terraform for S3, CloudFront, API Gateway, Lambdas, DynamoDB.

API (all under `/api`): `GET /items`, `POST /items`, `PATCH /items/{id}`, `DELETE /items/{id}`, `POST /items/clear-checked`.

DynamoDB: one table, `pk = LIST#family`, `sk = ITEM#<id>`.

### CloudFront-only API access

The API is not reachable except through CloudFront:

1. CloudFront adds a secret header (`x-origin-verify`) to every `/api/*` request it forwards. It overwrites any value a viewer sends.
2. Every API Gateway route uses a Lambda authorizer that requires that header to match the secret. A request without the header gets a 401 from API Gateway and never reaches the API Lambda; a wrong value gets a 403.
3. The secret is generated by Terraform (`random_password`) and shared by CloudFront and the authorizer. It is stored in Terraform state, so keep state private. Rotate with `terraform -chdir=infra apply -replace=random_password.origin_verify`.

(HTTP APIs don't support resource policies or WAF, hence the authorizer. Switching to a REST API + WAF is the alternative if you want it later.)

## Voice dictation

When the input is empty, the right-hand button is a mic. Tap it, say "milk, eggs and a loaf of bread", tap again, and three items are added. It uses the browser's built-in Web Speech API, so there is no backend, cost or extra infrastructure; the mic button simply doesn't appear in browsers without support (e.g. Firefox). `frontend/src/parseItems.ts` splits the transcript into items (commas, "and", "then"...; strips "add", "we need", "a", "some"...). Known limit: "mac and cheese" becomes two items.

Upgrade path if the rules prove too crude: add `POST /api/items/parse` that sends the transcript text (not audio) to an LLM (e.g. Bedrock) and returns item names.

## Local development

```bash
npm install
npm run dev      # Vite on :5173 + local API on :3001 (in-memory data, no AWS needed)
npm test         # backend unit tests
npm run typecheck
```

## Deploy

Prerequisites: Node 20+, Terraform ≥ 1.6, AWS CLI with credentials for the target account.

```bash
./scripts/deploy.sh
```

That installs, tests, builds both halves, runs `terraform apply` (it will show the plan and ask), uploads `frontend/dist` to S3 and invalidates CloudFront. It prints the site URL; open it on each phone and use *Share → Add to Home Screen*.

By hand: `npm run build`, then `terraform -chdir=infra init && terraform -chdir=infra apply`, then `aws s3 sync frontend/dist s3://$(terraform -chdir=infra output -raw site_bucket) --delete` and a CloudFront invalidation. The Lambda zip is built from `backend/dist`, so always build before `terraform apply`.

Check the lock-down after deploying:

```bash
curl -i "$(terraform -chdir=infra output -raw api_direct_url)/api/items"   # 401: direct access blocked
curl -i "$(terraform -chdir=infra output -raw site_url)/api/items"         # 200: via CloudFront
```

Settings are in `infra/variables.tf` (region, price class, API throttling, log retention). Terraform state is local by default; a commented S3 backend is in `infra/versions.tf`.

## Security

This MVP has no authentication. The CloudFront-only rule keeps people from hitting API Gateway directly, but anyone who knows the CloudFront URL can read and edit the list. Mitigations in place: API throttling (20 rps / 40 burst by default), input validation and length limits, no CORS. Planned next step: sign-in (e.g. Cognito) with the API Gateway authorizer checking tokens as well.

## Not included yet

Custom domain, auth, multiple lists, offline mode, editing an item's name from the UI (the API supports it).
